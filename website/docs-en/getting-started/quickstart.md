# Quickstart

XCPC Workstation ships with a complete built-in example workspace so you can walk through statement typesetting, full booklet PDF publishing, and CLI verification in a few minutes without manual setup. You can start with either the desktop app or the command line.

## Option 1: Desktop App (Recommended)

1. Launch **XCPC Workstation**.
2. On the welcome screen, click **New Workspace**. Choose a default template in the dialog, then select **Start from Example** and pick an empty folder to unpack the built-in example workspace; or choose **Empty Workspace** to start a clean library of your own.
3. The built-in Chinese example workspace includes:
   - **4 persistent groups** and **12 sample problems** (covering standard statements, Typst layout examples, and buildable problem packages)
   - **2 sample contests**: `welcome-round` using `olymp-classic`, and `oi-mock` using `cnoi-classic`
   - **4 sample algorithm snippets** and **1 sample Team Reference Document (TRD)** (`icpc-regional`)
4. Once inside the workspace, explore the core views in order:
   - In the **Problems** view, browse groups, search problems, inspect the statement preview on the right, and select multiple problems to try batch actions.
   - Click any problem or open **Contests → `welcome-round`** to enter the Publishing Studio. Edit Markdown or math in the editor and observe incremental live preview updates on the right.
   - Click **Export PDF** in the top bar and choose **Export Statements** or **Export Editorial** to generate the statement and editorial PDFs.
   - Press ++ctrl+k++ to open the **Command Palette** to jump to problems, contests, or views; type `>` to search executable actions only; press ++ctrl+slash++ to view the full keyboard shortcuts reference.

!!! tip "Switching Interface Language or Example Workspace"
    The desktop client supports live switching between Simplified Chinese and English under **Settings → Appearance**. To unpack the English example workspace, run `xcpc init --example --lang en ./my-xcpc-en` from the CLI and open that folder in the desktop app.

## Option 2: Command Line (CLI) Walkthrough

The following commands demonstrate how to unpack the example workspace with `xcpc` and run preflight checks, PDF builds, and per-page PNG rendering.

### 1. Initialize an Example Workspace

```bash
# Unpack the Chinese example workspace into ./my-xcpc
xcpc init --example ./my-xcpc
```

Common options:

- `--lang en` (or `--lang english`): Unpack the English example workspace (includes two contests: `welcome-round` and `minimal-round`).
- `--with-skills`: Also copy the official AI Skills into `.agents/skills/` inside the workspace.
- Without `--example` (`xcpc init ./my-xcpc`): Create a clean empty workspace containing `workspace.toml`, `problems/`, `contests/`, `templates/`, `.gitignore`, and `AGENTS.md`.

### 2. Inspect Workspace Contents and Fonts

```bash
# List all problems and contests in the workspace
xcpc -w ./my-xcpc list

# List font families currently detected by the typesetting engine
xcpc fonts
```

!!! note "Workspace Discovery Rules"
    `xcpc` resolves the workspace root (marked by the presence of `workspace.toml`) in the following order:
    1. CLI flag `-w <DIR>` / `--workspace <DIR>`
    2. Environment variable `XCPC_WORKSPACE`
    3. Walking upward from the current working directory

    If you run commands from inside `./my-xcpc`, `-w ./my-xcpc` can be omitted in the examples below.

### 3. Typesetting Check and Preflight (`xcpc check`)

`xcpc check` compiles the target document in full and runs typesetting and preflight checks without writing any output files:

```bash
# Check the full contest statement booklet
xcpc -w ./my-xcpc check contest welcome-round

# Check the full contest editorial booklet
xcpc -w ./my-xcpc check contest welcome-round --editorial

# Check a single problem (--json outputs structured diagnostics)
xcpc -w ./my-xcpc check problem crc-check --json
```

Exit code convention: `0` means no errors, `1` means document or preflight errors were found, and `2` indicates usage, workspace, or I/O errors.

### 4. Build PDFs (`xcpc build`)

```bash
# Build full statement and editorial booklets (output defaults to my-xcpc/build/)
xcpc -w ./my-xcpc build contest welcome-round
xcpc -w ./my-xcpc build contest welcome-round --editorial

# Build a single problem, or specify an explicit output path
xcpc -w ./my-xcpc build problem crc-check -o ./my-xcpc/build/crc-check.pdf

# Combine multiple problems into an ad-hoc PDF booklet
xcpc -w ./my-xcpc build problems crc-check tree-beacon --title "Weekend Practice" --cover true
```

To inspect typesetting details, append `--emit-typst <file.typ>` to write out the intermediate Typst source generated by the conversion pipeline.

### 5. Render Single-Page PNG Previews (`xcpc render`)

```bash
# Render page 1 of welcome-round as PNG (default scale = 2.0, ~144 DPI)
xcpc -w ./my-xcpc render contest welcome-round --page 1

# Render all pages of the statement booklet into a directory
xcpc -w ./my-xcpc render contest welcome-round -o ./my-xcpc/build/pages --scale 2.0
```

Rendered images are named `page-1.png`, `page-2.png`, and so on.
