# 产品定位与功能范围

## 1. 定位

XCPC Workstation 是本地优先、以桌面端为主的 **个人/小队 XCPC 全能工作站**：

- **题库是底座**：题目不依附于某一场比赛，而是独立持久化的一等公民，包含题面、样例、标签/难度、题解笔记、标程/AC 代码和训练状态。
- **比赛是题目的组合**：比赛通过「活引用 + 比赛级覆写」自由组题、安排难度曲线，一键生成与 `GassaFM/olymp.sty` 严格一致的纸质题目册（也可以同时生成官方题解册）。赛后可以一键冻结快照，防止内容随题库变化而漂移。
- **训练 Dashboard 形成闭环**：基于本地题库、做题记录和外部 OJ 同步数据，提供热力图、能力雷达、难度分布、VP 复盘和待补题队列。
- **Agent 是一等用户**：同一个 Rust 核心同时驱动桌面 GUI 和无头的 `xcpc mcp` / `xcpc --json`，详见 [architecture.md](./architecture.md#7-agent--mcp--cli)。

### 产品边界（明确不做）

- **不迁移 v1**：v1 是浏览器里的单场比赛题面生成器。本项目从零构建，不写任何 v1 数据或代码的迁移逻辑。
- **不导出 LaTeX**：只通过原生 Rust Typst → PDF 复刻 `olymp.sty` 的视觉样式，不提供 `.tex` 导出器。

## 2. 题目（Problem）

每道题在题库中独立持久化，包含 5 类核心资产：

1. **题面与样例**：多格式题面正文（默认 Markdown + Math，也支持 LaTeX、Typst）、样例输入输出对、时空限制、交互协议、配图。
2. **结构化元信息**：算法标签（DP、图论、网络流等）、难度评级（如 800–3500，或自定义梯度）、赛事来源、原题链接、作者，以及自定义键值属性。
3. **题解与笔记**：独立的 `editorial.md`（Markdown + LaTeX），记录思路和复杂度分析；导出比赛时可以一键生成**官方题解册 PDF**。
4. **代码附件**：可以挂载多份代码（`std.cpp`、个人 AC 代码、对拍脚本等），每份都带语言和用途标记。
5. **训练状态与做题记录**：未做 / 尝试中 / 赛时 AC / 补题 AC，以及耗时、罚时、错因标签和间隔重复复习提醒。

### 双语题面

单题原生支持 `statement.zh.md` 和 `statement.en.md` 两个语言槽位，二者共用同一份 `samples/`、`limits` 和 `assets/`。出版工作室提供双语并排校对视图，中文和英文题册可以分别一键导出。细节见 [statement-style.md](./statement-style.md#5-双语题面校对与语义级-diff)。

## 3. 比赛（Contest）

- **活引用 + 比赛级覆写**：比赛只保存题目 ID、题号（A/B/C…）、气球颜色和可选的局部覆写（例如这场比赛临时调紧时间限制或改显示标题）。题库里修正一处错别字，所有引用该题且**未冻结**的比赛都会自动同步。
- **一键冻结快照**：正式比赛印制或归档后，可以一键锁定这场比赛的题面和样例（`is_frozen = true`，内容写入 `snapshot/`），保证历史试卷永远可以复现，不随题库后续改动而漂移。
- **智能组题辅助**：组卷视图实时统计当前组合的**难度分布直方图**、**知识点标签覆盖率**和**预估总页数**；支持按条件从题库快速抽题（如「1800–2200 + 图论 + 近半年没用过」）。
- **封面与题表**：新建比赛默认带独立封面页和试题列表页，可以关闭，见 [statement-style.md](./statement-style.md#12-封面与试题列表页)。

## 4. 个人训练与 OJ 同步

### 4.1 6 平台分级同步（`xcpc-sync`）

| 梯队 | 平台 | 接入方式 |
| :--- | :--- | :--- |
| 第一梯队 | **Codeforces**、**AtCoder**（官方 / Kenkoooo）、**QOJ** | 免鉴权的公开 API 直连 |
| 第二梯队 | **洛谷**、**牛客**、**LeetCode** | 可选的本地 Cookie/Token，用系统钥匙串（`keyring`）加密存储；遇到反爬或风控时平滑降级为提示用户手动刷新，或通过浏览器扩展回传 |

### 4.2 同步记录与精选题库分层

- 海量的跨平台提交记录、Rating 变化、参赛排名、标签统计和赛程缓存，单独存放在 `.xcpc/oj_sync.db`，**不进入**由 Git 管理的 `problems/`。
- 只有当用户主动写题解、把题目加入题单或比赛、或通过 Competitive Companion 抓题时，才通过一键「收入本地题库（Promote）」写入 `problems/<id>/`；这时可以选择自动归档个人 AC 源码。

### 4.3 刷题画像与复盘

- **总览**：多平台账号和实时 Rating 徽章；今日 / 本周 / 本月 / 累计的 AC 数和提交数；**提交热力图与 AC 热力图双模式切换**，并带跨年选择器（`2026 / 2025 / 2024`）。
- **刷题画像**：多平台 Rating 曲线叠加、能力雷达图、平台过题环形图、难度分布直方图、可滚动的标签 AC Top 榜、跨平台近期提交时间线。
- **赛后复盘与自动补题**：每场外部比赛或本地 VP 都可以写独立的复盘笔记，并自动标出「赛时 AC / 赛后已补 / 待补题」状态；未补的题自动进入待补队列。

### 4.4 题单（Training Sheets）

支持自建或导入专题题单（`sheets/*.toml`）。题单会对照多平台同步记录自动点亮完成进度，也可以**一键把整份题单排册导出为 `olymp.sty` 纸质 PDF**。

## 5. 代码模板册（TRD）

把工作区 `templates/` 下的算法模板排版成纸质参考手册（Team Reference Document）。每段代码都带 KACTL 风格的 6 位哈希，可在赛场手敲后比对。详见 [statement-style.md](./statement-style.md#4-代码模板册trd)。

## 6. 赛事包与 OJ 生态互通

| 平台 / 格式 | 导入 | 导出 | 核心适配内容 |
| :--- | :---: | :---: | :--- |
| **Codeforces Polygon（ZIP）** | 完整 | — | `contest.xml`/`problem.xml`、多语言 `statement.tex`、样例、配图、时空限制、交互题标记 |
| **Competitive Companion（端口 `10043`）** | 实时抓取 | — | 桌面端常驻本地监听；在浏览器里刷 CF / AtCoder / QOJ / 洛谷时点一下插件，就能把题目元数据、样例、时空限制和链接收入本地题库 |
| **DOMjudge（ICPC Package）** | 支持 | 支持 | `problem.yaml`、`problem_statement/`、`data/sample/`、PDF 题面打包 |
| **Hydro OJ** | 支持 | 支持 | `problem.yaml`、`problem_zh/en.md`、样例与附加文件 |
| **FPS（XML）** | 支持 | 支持 | 题面、样例、Base64 图片、标程代码 |
| **QOJ / 通用 Markdown 包** | 支持 | 支持 | 规范 Markdown 题面 + 题解 + 静态资源归档 |
| **出版级 PDF** | — | 完整 | 整本题目册（封面、题表、奇偶页补白）、单题 PDF、官方题解册、代码模板册（TRD） |

另外提供轻量 Git 集成，并保留可选的云同步插件（OSS / COS / R2 / GitHub）。

## 7. 远期：Hull 式声明式本地 Polygon（Phase 5）

参考 [`rindag-devs/hull`](https://hull.aberter0x3f.top/)。`problem.toml` **现在**就预留可选的声明式命名空间（`subtasks` / `generators` / `validators` / `checkers` / `solutions` 及其期望评测结果）和目录扩展位，但 Phase 1–4 不实现。Phase 5 计划基于 Rust 原生的 WASI/WASM 确定性沙箱（`wasmtime`）实现跨平台、可复现的造数据、Subtask/Trait 校验、Checker 验证、多解法期望结果测试和对拍，兼容 Testlib / CPLib，并与 Hull 工程双向互通。
