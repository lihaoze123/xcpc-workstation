# Spec：去预设特权、单入口模板契约与比赛级版式定制

> 状态：已确认（2026-11-22 `/grill-me` 共识），待实现。  
> 关联文档：[statement-style.md](../statement-style.md)、[product.md](../product.md)、[architecture.md](../architecture.md)、[design-system.md](../design-system.md)、[roadmap.md](../roadmap.md)。

---

## 1. 背景与痛点

在 Phase 2.5C 第一版落地后，虽然已经实现了声明式 `#let schema` 与属性面板双 Tab，但仍然存在两类结构性瓶颈，导致用户想定制一场比赛的模板时「改无可改」：

1. **预设模板过于「一等公民」（只读特权）**：
   - `olymp-classic` 与 `cnoi-classic` 通过 `include_str!` 硬编码在引擎二进制中并作为隐式内置回退；
   - 界面禁止直接编辑内置模板（强制用户先 fork 起新名字），也不支持单场比赛专属的 `contests/<id>/template.typ`；
   - 用户想给某一场具体比赛加校徽、改封面结构或微调页眉页脚时，无法直接拿到并修改正在生效的 `.typ` 源码。
2. **Core 与 UI 过度绑定预设模板假设**：
   - `cover`、`blank-pages`、`show-metadata` 被写死在 `contest.toml` 顶层与 `Inspector` 的「版式」Tab 顶部，自定义模板既无法接管也无法隐藏它们；
   - 转换管线生成的 Typst 强制要求每个模板实现固定的 7 个具名函数签名（`contest / problem / section / samples / tutorial / subsection / runin`），参数列表僵硬、难以从零编写，且限制了模板对封面、题表、分页与多栏布局的掌控。

## 2. 设计原则与非目标

### 设计原则
- **开放目录即单一事实源**：所有生效模板都是工作区或比赛目录里真实存在的 `.typ` 文件，平等可编辑、可进 Git。
- **预设仅作「模板种子」**：内置的 `olymp-classic`、`cnoi-classic`、`minimal` 没有任何运行时特权或隐式回退，只用于初始化工作区与「从预设添加模板」。
- **单入口、低门槛、高自由度**：模板只需导出 `#let render(doc)` 即可接管整本 PDF 排版，其余辅助钩子均有默认实现。
- **做减法**：不引入应用内 Typst IDE，所有代码编辑继续交由系统外部编辑器 + `notify` 实时热刷新。

### 明确不做
- 不做应用内 Typst 代码编辑器 / LSP；
- 不做运行时「内置回退」魔法（缺失模板明确报错并引导一键安装）；
- 不做历史工作区自动静默迁移（打开缺少模板文件的目录时只提示，不擅自写盘）。

## 3. 模板存放、解析优先级与落盘模型

### 3.1 磁盘布局
```text
xcpc-workspace/
├── workspace.toml                  # 默认 template = "<name>" 与 [template-options.<name>]
├── templates/                      # 工作区模板目录（全部为普通可编辑 .typ 文件）
│   ├── olymp-classic.typ
│   └── cnoi-classic.typ
├── assets/                         # 工作区级共享图片资源（如通用校徽/Logo）
├── .xcpc/
│   └── preamble.typ                # 工作区级 Typst 宏与样式注入（可选）
└── contests/
    └── <contest-id>/
        ├── contest.toml            # 可选 template = "<name>" 与 [template-options.<tpl>]
        ├── template.typ            # 可选：本场比赛专属模板（存在即优先）
        ├── assets/                 # 本场比赛专属图片资源（如本场封面徽标）
        └── snapshot/               # 定稿快照：固化生效 template.typ / preamble.typ / template.toml / assets
```

### 3.2 严格解析优先级（无内置回退）
1. **定稿比赛**：若 `contest.meta.frozen == true`，严格读取 `contests/<id>/snapshot/template.typ`、`snapshot/preamble.typ` 与 `snapshot/template.toml`；
2. **比赛专属模板**：若 `contests/<id>/template.typ` 存在，直接使用该文件（忽略 `contest.toml` / `workspace.toml` 的 `template` 字段），参数命名空间固定为 **`local`**；
3. **工作区模板**：按 `contest.meta.template` → `workspace.toml` 的 `template` → `"olymp-classic"` 确定模板名 `<name>`，检查 `templates/<name>.typ` 是否存在；
4. **缺失处理**：若目标 `.typ` 文件不存在，编译直接返回 `error: true, code: "missing_template"` 诊断（**不回退到二进制内置模板**）。GUI 在「版式」Tab 顶部给出克制的提示卡片与「从预设安装」一键按钮。

### 3.3 预设种子与按需落盘
- 引擎/存储层提供 3 个预设种子（`PresetInfo { id, name, description }`）：
  1. `olymp-classic`：对齐 `olymp.sty` 的经典 ICPC / XCPC 版式（默认输出与 `polygon-chinese-template@10f9959` 视觉回归逐页一致）；
  2. `cnoi-classic`：CCF CSP-J/S 与 NOI 官方风格题面与题解；
  3. `minimal`：约 40 行的极简空白起点模板，方便从零编写自定义比赛模板。
- **落盘时机**：
  - `xcpc init` / GUI「新建工作区」：仅把选中的 1 份默认预设落盘到 `templates/<name>.typ`；
  - `xcpc init --example` / GUI「打开示例」：落盘示例比赛实际引用的 `templates/olymp-classic.typ` 与 `templates/cnoi-classic.typ`；
  - 「从预设添加模板」：用户在「设置 → 排版」或模板选择器中随时从 3 个种子安装到 `templates/<target>.typ`（拒绝静默覆盖同名文件）；
  - 回归脚本 `scripts/fixture-to-workspace.py`：生成基准工作区时同步落盘 `templates/olymp-classic.typ`。

## 4. 单入口数据驱动契约：`#let render(doc)`

### 4.1 转换管线生成的 `/main.typ` 结构
`xcpc-convert` 将工作区数据编译为如下单入口调用：

```typst
// Generated by xcpc from the workspace: edit the workspace, not this.
#import "/xcpc/defaults.typ": section, samples, subsection, runin
#import "<resolved-template-path>" as __xcpc_tpl
#import "<resolved-template-path>": *
#import "/xcpc/markdown.typ": m, dm

// （若存在 .xcpc/preamble.typ，在此处带 SourceMap 标记注入，使自定义宏在所有 body 内可见）

#__xcpc_tpl.render((
  name: "...",
  location: none,           // string | none
  date: none,               // string | none
  author: none,             // string | none
  language: "chinese",      // "chinese" | "english"
  book: "statements",       // "statements" | "editorial"
  single: false,            // bool（单题预览/导出为 true）
  pdf-title: "...",         // string | none
  pdf-author: "...",        // string | none
  options: (...),           // 合并后的 book 级模板参数字典
  problems: (
    (
      id: "two-sum",
      label: "A",
      title: "Two Sum",
      author: none,         // string | none
      rating: 800,          // int | none
      tags: ("greedy",),    // array of string
      sources: (            // array of (platform:, id:, url:)
        (platform: "codeforces", id: "1999A", url: "..."),
      ),
      input: none,          // string | none
      output: none,         // string | none
      time-limit: "1 秒",   // 按 language 格式化后的字符串 | none
      memory-limit: "256 MB",
      samples: (("1 2\n", "3\n"),),
      options: (...),       // 合并后的单题级模板参数字典
      meta: ("作者 ...",),  // 题解副标题元信息数组
      body: [
        // 转换后的 Markdown 内容，所有段落/公式/代码块保留精确 SourceMap 字节偏移
      ],
    ),
  ),
))
```

### 4.2 关键设计保障
- **可选覆写钩子（`/xcpc/defaults.typ`）**：先导入 `/xcpc/defaults.typ` 的 `section`、`samples`、`subsection`、`runin`，再 `#import "<template>": *`。模板导出同名函数即自动覆盖默认实现；极简模板可以只写 `#let render(doc)` 而完全不实现这些辅助函数。
- **无痛封面与目录**：`doc.problems` 直接包含所有题目的元数据、限值与数量，封面表不再强依赖 `state` 回溯技巧；同时模板仍可继续使用 `#metadata((label:, title:)) <xcpc-problem>`（或 `<xcpc-tutorial>`）向 Core 报告每题起始页码，供大纲跳页与组题统计使用。
- **保留双向定位（`SourceMap`）**：`body: [...]` 仍是 `/main.typ` 内的原生 Typst content，预览 `Ctrl+点击` 跳回 Markdown 源码行、编辑器 `Mod+Shift+L` 跳预览及诊断行列映射均 100% 保持精确。

## 5. 去特权开关与全平权 `#let schema`

### 5.1 Core 内容层 vs 模板版式层边界
| 层级 | 包含字段 | 归属位置 |
| :--- | :--- | :--- |
| **Core 纯业务数据** | 比赛：`name`、`location`、`date`、`author`、`language`、`frozen`、`[[problem]]`<br>题目：`title`、`rating`、`tags`、`author`、`limits`、`[[source]]` | 固定在 `contest.toml` / `problem.toml` 与属性抽屉「信息」Tab |
| **模板版式参数** | `cover`、`blank-pages`、`show-metadata`、`logo`、字号/边距/字体、样例样式、编译选项、注意事项、单题类型等 | 全部由各模板在 `#let schema = (...)` 中声明，按模板名隔离存储并在「版式」Tab 动态渲染 |

> **兼容过渡**：`ContestMeta` / `ContestItem` 在读取现有 `contest.toml` 时，若顶层仍存在历史键 `cover` / `blank-pages` / `show-metadata` 且对应 `[template-options.<tpl>]` 未显式设置，转换层可将其折入 `options`；但 UI「版式」Tab 彻底移除硬编码开关，所有新写入均落入命名空间化的 `[template-options.<tpl>]` / `[problem.options.<tpl>]`。

### 5.2 9 种 Schema 参数类型
在已有 8 种类型（`bool`、`enum`、`string`、`lines`、`number`、`length`、`color`、`font`）基础上新增第 9 种：

- **`image`**：
  - 值形态：工作区相对路径字符串（如 `"contests/icpc-2026/assets/logo.png"` 或 `"assets/school-logo.svg"`），空字符串 `""` 表示不显示；
  - 模板内用法：因路径相对工作区根，模板可直接 `image("/" + path, ...)` 加载（无需关心模板自身在 `templates/` 还是 `contests/<id>/`）；
  - GUI 控件：显示当前文件名/缩略预览 +「选择图片」按钮（调用系统文件选择器，原子导入到 `contests/<id>/assets/` 或工作区 `assets/`，防覆盖重名）+「清除」按钮。

### 5.3 三级作用域与命名空间隔离
- **命名空间规则**：
  - 引用工作区模板 `templates/<name>.typ` 时，命名空间为 `<name>`；
  - 使用比赛专属 `contests/<id>/template.typ` 时，命名空间固定为 `local`（即 `contest.toml` 的 `[template-options.local]` 与 `[problem.options.local]`）。
- **合并优先级**：
  - `book` 级：`模板 schema 默认值` → `workspace.toml [template-options.<tpl>]` → `contest.toml [template-options.<tpl>]`（`local` 模板不继承其他工作区模板参数）；
  - `problem` 级：`模板 schema 默认值` → `problem.toml [template-options.<tpl>]` → `contest.toml [[problem]] [problem.options.<tpl>]`。
- 所有 TOML 写回统一走 `toml_edit`，保留注释与未知字段；覆写值回到上级值时自动清理冗余键与空表。

### 5.4 预设种子开放的 Schema 清单
- **`olymp-classic`**：
  - 分组：`出版与封面`（`cover`: auto/on/off、`logo`: image、`show-metadata`: bool、`blank-pages`: bool）、`页面与字体`（`body-size`、`margin-x`、`margin-y`、`cjk-body-font`、`cjk-heading-font`）、`单题排版`（`show-metadata`: bool、`sample-layout`: two-column/wide）；
  - 默认参数下输出与 `polygon-chinese-template@10f9959` 基准回归逐页一致。
- **`cnoi-classic`**：
  - 分组：`封面与考试说明`（`cover`、`logo`、`compile-opts`、`show-submit-table`、`show-compile-table`、`notices`）、`样例与正文样式`（`show-metadata`、`blank-pages`、`sample-border-color`、`sample-line-numbers`、`dotted-emphasis`）、`页面与字体`（`body-size`、`margin`、`cjk-body-font`、`cjk-heading-font`）、`单题设置`（`show-metadata`、`prob-type`、`source-file`）。
- **`minimal`**：
  - 极简示例 schema（`body-size`、`margin`、`show-cover`），便于用户对照学习并快速魔改。

## 6. 定稿快照归档规则

`freeze_contest` 冻结比赛时，必须保证快照在脱离外部工作区环境后仍可 100% 复现：
1. 复制当前生效的模板源码（无论是 `contests/<id>/template.typ` 还是 `templates/<name>.typ`）到 `contests/<id>/snapshot/template.typ`；
2. 若 `.xcpc/preamble.typ` 存在且非空，复制到 `contests/<id>/snapshot/preamble.typ`；
3. 将合并后的 `book` 级模板参数写入 `contests/<id>/snapshot/template.toml`（其中 `image` 类型参数若引用了 `assets/` 或 `contests/<id>/assets/` 下的图片，一并复制到 `snapshot/assets/` 并重写快照内相对路径）；
4. 每题目录 `snapshot/<label>/problem.toml` 继续合并 `[[problem]]` 的元数据与单题级模板参数覆写。

## 7. CLI、MCP 与桌面端交互规范

### 7.1 CLI（`xcpc`）
- `xcpc template list [--json]`：列出工作区 `templates/*.typ` 的全部模板、当前默认模板，以及可安装的预设种子列表；
- `xcpc template schema <name> [--json]`：输出指定工作区模板解析后的 `#let schema`；
- `xcpc template add <preset> [name] [--json]`：从预设种子（`olymp-classic` / `cnoi-classic` / `minimal`）安装一份可编辑模板到 `templates/<name>.typ`（缺省 `name = preset`）；
- `xcpc template fork <source> <new_name> [--json]`：复制现有工作区模板到 `templates/<new_name>.typ`。

### 7.2 MCP（`xcpc mcp`）
- `list_templates`（只读）：返回 `{ default, workspace_options, templates, presets }`；
- `add_template`（写入，受 `--read-only` 守卫）：从预设种子安装到 `templates/<name>.typ`；
- `set_template_options`（写入）：支持 `scope: "workspace" | "contest" | "problem"`，当比赛启用了 `contests/<id>/template.typ` 时支持对 `local` 命名空间写入参数。

### 7.3 桌面端 UI
- **属性抽屉「信息」Tab**：
  - 比赛上下文：定稿状态卡 + 比赛信息（名称、日期、地点、署名、**语言**）+ 当前题元数据覆写（标题、时间/空间限制、输入/输出文件）+ 素材库入口；
  - 单题上下文：题目信息 + 素材库入口。
- **属性抽屉「版式」Tab（比赛上下文）**：
  - **模板区**：
    - 常规态：显示 `TemplatePicker`（列出 `templates/*.typ` + 底部「从预设添加模板…」菜单项），下方提供操作：
      - 「编辑模板」（直接用系统编辑器打开 `templates/<name>.typ`，**不再有任何内置模板不可编辑限制**）；
      - 「独立为本场模板」（复制当前模板到 `contests/<id>/template.typ`，独立定制本场比赛）。
    - 专属模板态（存在 `contests/<id>/template.typ`）：顶部清晰标示「本场专属模板」，提供「编辑本场模板」与「恢复引用工作区模板」（移除 `contests/<id>/template.typ`，带确认）。
    - 缺失模板态：展示明确提示与一键「从预设安装」按钮。
  - **动态参数区**：100% 由当前生效模板的 `#let schema` 驱动，每个 `group` 渲染为独立的一级 `Section`（`12.5px SemiBold` 主文本色 + `1px` 分割线），支持 9 种控件（含 `image` 选图导入）与覆写竖条/一键还原。
  - **进阶定制区**：「新建模板副本」与「自定义样式代码」（打开 `.xcpc/preamble.typ`）。
- **属性抽屉「版式」Tab（单题上下文）**：
  - 展示当前沿用的工作区默认模板名 +「调整工作区默认版式」跳转「设置 → 排版」；
  - 渲染 `scope: "problem"` 的动态字段（写回 `problem.toml`）。
- **「设置 → 排版」**：
  - 选择工作区默认模板（`templates/*.typ`）、提供「从预设添加模板」「编辑模板」「新建副本」「自定义样式代码」；
  - 渲染工作区级 `scope: "book"` 默认参数（支持一键「恢复默认」）。
