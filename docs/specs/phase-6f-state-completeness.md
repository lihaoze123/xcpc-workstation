# Phase 6F 规格：状态完整性

2026-11-26 grill-me 对齐确认，在 Phase 6D（Token 与重点界面）与 6E（排版）之后进行。

6D、6E 解决的是默认状态下「同一件事只有一种做法」。本阶段补齐默认状态之外的部分：文字截断后、窗口失焦时、空、加载、出错、极端数据下，界面同样经过设计。现状核查：

- 45 个文件截断文字（`numberOfLines` + `textOverflow`），其中只有 11 个配了 Tooltip。
- 选中态已统一为浅灰（design-system.md §3.1），品牌色只剩实色元素；窗口前后台不影响任何显示。NSH 提供响应式 `lifecycle()`（`"active" | "inactive" | "background"`）。
- `ErrorDisplay`（15 个文件）、`EmptyState`（12 个）、`DelayedSpinner`（13 个）均已存在，缺的是「什么范围用哪种」的规定；「还没有内容」与「筛选后无结果」多处共用同一个 `EmptyState`。
- 题库、命令面板为虚拟列表，提交记录分页；比赛、代码片段、TRD 列表用 `<Each>` 全量渲染。
- `kit.tsx` 已有统一的 `FOCUS_RING`（1px 内描边），12 个文件在用，覆盖不全。

本规格落地后同步改写 [design-system.md](../design-system.md)：§9（交互工艺细则：截断 Tooltip、失焦指示条、聚焦环覆盖规则）与 §9.1（三级状态表、筛选无结果）。

---

## 1. 截断文字的 Tooltip

- 新增截断文本组件（放在 `kit.tsx`），用 `<Text>` 的 `onTextLayout` 比对排版结果与原文，**只在确实被截断时**挂 Tooltip。
- 延迟与样式沿用 `tip()`：`600ms`、上方弹出。最大宽度 `360`，超出换行，最多 4 行。
- 全局替换 45 处手写截断；已有的 11 处手写 Tooltip 并入该组件。
- **前置验证**：实现前先确认 `onTextLayout` 能可靠判断截断。不可靠则本节整体不做，不退化为「所有可截断位置一律挂 Tooltip」。

## 2. 窗口失焦

- 新增全局 `windowActive` signal（`lifecycle() === "active"`）。
- 窗口失焦时，**只有指示条**（导航栏选中指示条、下划线 Tab 指示条）由 `primary` 变为 `muted-foreground`；只换颜色，不改尺寸。
- 主按钮不变（它表示可执行的主动作，与前后台无关）；焦点环本就只在窗口激活时出现。

## 3. 空、加载、出错：三级规则

按作用范围分三级，每级只有一种表现：

| 范围 | 空 | 加载 | 出错 |
| :--- | :--- | :--- | :--- |
| **页级**（整个内容区） | `EmptyState`：图标 + 一句话 + 一个动作 | `150ms` 后中央 `DelayedSpinner` | 居中 `ErrorDisplay` |
| **区块级**（卡片 / 面板内） | 一行浅色文字，无图标 | 原位保留上次内容，不转圈 | 左对齐 `ErrorDisplay`（预留高度） |
| **行级** | 按 6D §6，空值不画 | 无 | 行尾警示图标，悬停看原因 |

- **「还没有内容」与「筛选后无结果」分开**：后者不放图标，只有一行「没有匹配的 <对象>」加「清除筛选」文字按钮。
- **不做骨架屏**：本地加载很快，骨架屏一闪而过形同闪烁；区块刷新保留旧内容，与「零闪白」一致。
- 用户触发动作的结束反馈仍按 design-system.md §6.5（原位瞬态确认 / 单槽 Toast），本节不改。

## 4. 极端数据

验收时逐条手动检查，不进 CI：

| 情形 | 测试数据 | 检查点 |
| :--- | :--- | :--- |
| 超长文本 | 200 字无空格中文题名、80 字符 slug、深层文件路径 | 按 §1 截断并有 Tooltip；周围布局不被撑开 |
| 只有 1 条 | 1 道题、1 场比赛、1 条提交、Rating 只有 1 个点 | 图表不退化为一条线或空白；列表不像坏了 |
| 数量很多 | 3000 道题、200 场比赛、500 个代码片段 | 滚动流畅，筛选 1 帧内响应 |
| 全空 | 新建空工作区 | 走 §3 页级空状态 |
| 英文界面 | 界面语言切到英文，走一遍 6 个空间与出版工作室 | 按钮、Tab、表头不被截断或撑开；文案更长处仍按 §1 截断 |

- 测试工作区用临时脚本生成，放 scratchpad，不进仓库。
- `<Each>` 全量渲染的列表在上述数据量下实测卡顿才改为虚拟列表，不卡不动。

## 5. 聚焦环审计

- 样式不变：`FOCUS_RING`（`ring-1 ring-inset ring-ring`，占 0 布局空间，不被 `overflow: hidden` 裁掉）。
- 所有可 Tab 聚焦的可按压元素必须带 `FOCUS_RING`：能换成 `Btn` / `IconBtn` / `Chip` 的换掉，不能换的手动补。
- Tab 顺序与视觉阅读顺序一致（上到下、左到右）。

## 6. 执行顺序与验收

每步一个 jj 提交；提交前跑通与 `.github/workflows/lint.yml` 一致的本地检查。

1. **文档同步**：改写 design-system.md §9、§9.1。
2. **截断 Tooltip**（§1，含前置验证）。
3. **窗口失焦**（§2）。
4. **三级状态**（§3）：逐屏填状态矩阵（屏幕 × 空 / 加载 / 出错 / 筛选无结果），每格能指出用的是哪一级哪种表现，再按矩阵改。
5. **聚焦环审计**（§5）。
6. **验收**：按 §4 清单逐条检查；状态矩阵与截图（浅色 / 深色）交用户确认。截图放临时目录，不进仓库。

## 7. 明确不做

- 骨架屏；全键盘列表操作；新增快捷键。
- 聚焦环改为外描边或改变样式。
- 失焦时改变主按钮、焦点环或选中底色。
- 极端数据的自动化测试或压测脚本入库。
- 无检测的「一律挂 Tooltip」退化方案。
