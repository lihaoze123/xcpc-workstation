# i18n 国际化支持规格

状态：已确认（2026-11-22）

## 1. 目标与范围

为 XCPC Workstation 桌面端及声明式模板体系提供简洁、零依赖、即时生效的多语言支持。

### 覆盖范围（In Scope）

1. **桌面端 GUI 界面文案**（`apps/desktop`）：覆盖导航、品牌页、题库、比赛、出版工作室、属性抽屉、素材库、设置、快捷键速查、`Cmd+K` 命令面板、`/` 斜杠命令、弹窗、提示、错误文案与原生文件对话框标题。
2. **模板 `#let schema` 多语言文案**（`xcpc-domain`、`xcpc-engine`、预设模板种子与桌面端渲染）：让预设模板与用户自定义 `.typ` 模板都能声明多语言分组、字段、描述、选项与占位符，且对单语自定义模板零负担。

### 明确不做（Out of Scope）

- **Core / CLI 人类可读输出**：`xcpc` CLI 输出、`xcpc-storage::Error::human_message()`、`xcpc-lint` 诊断文案、默认导出文件名、内置示例工作区内容不在本次范围内。
- **Typst 编译器原始诊断**：保持 Typst 原始英文诊断输出，不做二次翻译。
- **题面出版语言扩展**：`xcpc-domain::Language` 仍保持 `chinese | english`，本次不新增出版语言，也不做双语并排校对。

## 2. 支持语言、系统检测与持久化

### 2.1 语言标识

- **有效界面语言（`Locale`）**：首批内置 `"zh-CN"`（简体中文）与 `"en"`（English）；架构按语言代码表驱动，预留扩展其他语言（如 `zh-TW`、`ja` 等）的能力。
- **用户偏好（`LanguagePref`）**：`"system" | "zh-CN" | "en"`，默认 `"system"`。

### 2.2 系统语言检测

桌面端 Rust 桥接层（`apps/desktop/src/lib.rs`）提供 `Preview.systemLocale(): string`（静态或实例方法），启动时同步读取操作系统语言并归一化：

- **Linux**：依次读取环境变量 `LC_ALL` → `LC_MESSAGES` → `LANG` → `LANGUAGE`（取冒号分隔的首个非空项，剥离 `.UTF-8` / `@modifier` 后缀，将 `_` 规范化为 `-`）。
- **Windows**：优先调用系统 locale API（如 `GetUserDefaultLocaleName`），失败时回退到环境变量。
- **映射规则**：
  - 忽略大小写，以 `zh` 开头 → `"zh-CN"`；
  - 其余（包括 `C`、`POSIX` 或检测失败）→ `"en"`。

### 2.3 持久化

- 在 `AppPrefsJs` 与 `<dataDir>/prefs.json` 中新增可选字段 `language?: "system" | "zh-CN" | "en"`（缺省或无法识别时视为 `"system"`）。
- 读写沿用既有 `prefs.rs` 原子写入与防抖机制，不影响其他偏好字段。

### 2.4 切换入口与交互

- **入口位置**：「设置 → 外观」（`Settings → Appearance`），与主题模式（`浅色 / 深色 / 跟随系统`）同页放置，提供 `跟随系统 / 简体中文 / English`（英文界面下为 `System / 简体中文 / English`——语言自称始终使用该语言自身名称）。
- **品牌页（`NoWorkspaceView`）**：不额外增加语言切换器，首次启动直接按系统语言呈现。
- **热切换**：通过响应式 `signal` 驱动全树更新，切换语言后当前帧即时刷新全部界面文本、窗口标题与模板 Schema 控件，无需重启、零闪白、不丢失编辑器状态与光标。
- **原生对话框**：Rust 侧 `OpenDialog`（打开工作区、选择封面徽标、导入素材图片等）接受由 JS 传入的本地化标题，避免在英文界面弹出中文系统对话框标题。

## 3. 模板 `#let schema` 多语言规范

### 3.1 多态 `LocalizedText` 声明格式

模板 `.typ` 文件的 `#let schema = (...)` 中，所有面向用户展示的文本字段均支持**多态写法**：

1. **纯字符串**（单语模板，向后兼容、零心智负担）：
   ```typst
   #let schema = (
     name: "My Custom Template",
     fields: (
       (key: "cover", label: "Cover", type: "bool", scope: "book", default: true),
     ),
   )
   ```
2. **多语字典**（多语言模板，键为 BCP 47 语言标签或主语言子标签，如 `zh` / `zh-CN` / `en`）：
   ```typst
   #let schema = (
     name: (zh: "XCPC 经典", en: "XCPC Classic"),
     description: (
       zh: "对齐 olymp.sty 的经典 ICPC / XCPC 版式",
       en: "Classic ICPC / XCPC layout aligned with olymp.sty",
     ),
     groups: (
       (id: "publishing", label: (zh: "出版与封面", en: "Publishing & Cover")),
     ),
     fields: (
       (
         key: "cover",
         label: (zh: "封面与目录", en: "Cover & Table of Contents"),
         type: "enum",
         scope: "book",
         group: "publishing",
         default: "auto",
         choices: (
           (value: "auto", label: (zh: "自动（多题时显示）", en: "Auto (multi-problem)")),
           (value: "on", label: (zh: "总是显示", en: "Always")),
           (value: "off", label: (zh: "不显示", en: "Off")),
         ),
       ),
     ),
   )
   ```

支持多态 `LocalizedText` 的字段清单：
- `schema.name`
- `schema.description`
- `schema.groups[].label`
- `schema.fields[].label`
- `schema.fields[].description`
- `schema.fields[].choices[].label`
- `schema.fields[].placeholder`

### 3.2 回退解析规则

给定目标界面语言 `locale`（如 `"zh-CN"` 或 `"en"`），解析 `LocalizedText`（Rust 与 TypeScript 实现完全一致）：

1. 若为纯字符串，直接返回该字符串。
2. 若为字典：
   1. 精确匹配（忽略大小写，且 `_` 与 `-` 等价，如 `"zh-CN"` 匹配 `"zh-cn"`）；
   2. 主语言子标签匹配（取 `-` 前部分，如 `"zh-CN"` 匹配 `"zh"`；或字典中首个同主语言键如 `"zh-Hans"`）；
   3. 回退到 `"en"`；
   4. 回退到 `"zh"` / `"zh-CN"`；
   5. 回退到字典按 key 排序的首个非空值；
   6. 仍无匹配返回空字符串 `""`。

### 3.3 Core、桥接与预设种子

- **`xcpc-domain`**：新增 `LocalizedText` 类型：
  ```rust
  #[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
  #[serde(untagged)]
  pub enum LocalizedText {
      Plain(String),
      Map(BTreeMap<String, String>),
  }
  ```
  提供 `LocalizedText::resolve(&self, locale: &str) -> &str` 辅助方法。`TemplateSchema`、`TemplateGroup`、`TemplateField`、`TemplateChoice` 中对应展示字段切换为 `LocalizedText`（或 `Option<LocalizedText>`）。
- **`xcpc-engine/src/schema.rs`**：解析函数同时接受 `Value::Str` 与 `Value::Dict`（仅提取字符串条目；空字典按缺失处理）。
- **桌面端桥接**：`TemplateSchema` 经 JSON 原样透传给前端（纯字符串或 `{ zh, en }` 对象），前端渲染时按响应式 `locale()` 实时调用 `resolveLocalized(text)`，切换界面语言时**无需重新求值 Typst**。
- **预设种子**：同步为以下三个预设模板的 `#let schema` 补齐 `zh` 与 `en` 双语声明：
  - `crates/xcpc-engine/templates/olymp-classic.typ`
  - `crates/xcpc-engine/templates/cnoi-classic.typ`
  - `crates/xcpc-engine/templates/minimal.typ`

## 4. 桌面端 GUI i18n 架构

### 4.1 零依赖强类型词典

`apps/desktop` 为纯 NSH TSX 工程，不引入第三方 npm i18n 库，在 `apps/desktop/src/ui/i18n/` 下组织：

```text
apps/desktop/src/ui/i18n/
├── index.ts    # Locale / LanguagePref 类型、响应式 signal、t()、resolveLocalized()
├── zh-CN.ts    # 简体中文词典（作为键集合与参数签名的主定义）
└── en.ts       # 英文词典（受 zh-CN 键集合类型约束）
```

### 4.2 API 设计

```ts
export type Locale = "zh-CN" | "en";
export type LanguagePref = "system" | Locale;

export const languagePref = signal<LanguagePref>("system");
export const locale = computed<Locale>(() => ...);

export function t(key: MessageKey, params?: Record<string, string | number>): string;
export function resolveLocalized(text: LocalizedText | undefined | null, loc?: Locale): string;
```

- **插值语法**：使用 `{name}` 占位符（如 `"{count} 题"` / `"{count} problems"`）；英文单复数差异明显处可拆键或按需在调用点选择（如 `count === 1`）。
- **编译期安全**：`en.ts` 的类型约束为 `Record<keyof typeof zhCN, string>`，漏翻或多键在 `nsh check` 阶段直接报错。
- **单元测试**：在 `apps/desktop` 的 `*.test.tsx` 中校验 `zh-CN` 与 `en` 键集合一致、所有 `{param}` 占位符集合一致、以及 `resolveLocalized` 的各条回退路径。

### 4.3 模块内文案拆分与边界规则

1. **避免模块顶层冻结翻译文本**：当前部分文件在模块加载时定义了静态数组（如 `SettingsView.tsx` 的 `NAV_ITEMS` / `APPEARANCE_OPTIONS`、`StudioView.tsx` 的 `TABS`、`ShortcutsModal.tsx` 的快捷键分组、`SlashPopover.tsx` 的命令列表）。改为存翻译 key 或在渲染/计算属性中读取 `t(...)`，确保热切换语言时全部更新。
2. **`Cmd+K` 与 `/` 斜杠命令**：
   - 展示标题与描述跟随当前界面语言；
   - 检索 `keywords` 保留中英双语（及拼音简写），用户在英文界面输入中文/拼音、或在中文界面输入英文关键词均可命中。
3. **`/` 斜杠命令插入的 Markdown 片段**：
   - 对含自然语言文字的插入片段（`hint` 提示章节、`interaction` 交互章节、`subtasks` 子任务评分表、`table` 表格表头），插入内容**跟随当前题面或比赛的出版语言**（`chinese` / `english`）；
   - 单题编辑且未显式指定出版语言时，回退到当前界面语言；
   - 英文出版语言对应的默认插入文本：
     - `hint`：`## Note\n\n`
     - `interaction`：`## Interaction\n\n`
     - `table`：`| Column 1 | Column 2 |\n| --- | --- |\n|  |  |`
     - `subtasks`：`| Subtask | Score | Constraints |\n| :---: | :---: | --- |\n| 1 | 20 | $n \le 10$ |\n| 2 | 30 | $n \le 1000$ |\n| 3 | 50 | No additional constraints |`
4. **错误展示（`ErrorDisplay` / `logic.ts`）**：
   - `errorCopy(code, raw)` 与 `diffKind(kind)` 改由 `t(...)` 输出对应语言的克制三段式文案；
   - 底层错误码与原始 `error` 仍只在「复制详情 / Copy Details」中暴露。

## 5. 英文核心术语与文案风格

英文文案严格延续 [design-system.md §7](../design-system.md#7-文案克制规范) 的克制原则（去内部术语、不道歉、不用感叹号、成功态静默、数字 `tabular-nums`）：

| 中文界面 | 英文界面 | 说明 |
| :--- | :--- | :--- |
| 题库 / 比赛 / 设置 | Problems / Contests / Settings | 左侧导航三个空间 |
| 题面 / 样例 / 题解 | Statement / Samples / Editorial | 编辑器三个 Tab |
| 属性（信息 \| 版式） | Properties (Info \| Layout) | 右侧抽屉与双 Tab |
| 定稿 / 已定稿 / 重新编辑 | Finalize / Finalized / Reopen | 对应内部 `freeze / frozen / unfreeze`，延续去技术术语风格 |
| 归档 / 已归档 / 取消归档 | Archive / Archived / Unarchive | 比赛归档收纳 |
| 导出 PDF / 导出题面册 / 导出题解册 | Export PDF / Export Statements / Export Editorial | 导出分体按钮与菜单 |
| 在文件夹中显示 | Reveal in Folder | 系统文件管理器打开 |
| 专注模式 | Focus Mode | 写作专注模式 |
| 素材库 | Assets | 题目配图画廊弹窗 |
| 跟随系统 / 浅色 / 深色 | System / Light / Dark | 外观主题选项 |
| 复制详情 | Copy Details | 错误详情复制 |
| 献给每一个和 WA 较劲到深夜的人 | For everyone who has fought a WA late into the night. | 「关于」页末行献词 |

## 6. 文档同步与验收

实现完成后同步更新以下规格文档：
- [docs/statement-style.md](../statement-style.md) §2.3：补充 `#let schema` 的多态 `LocalizedText` 声明规范与回退规则。
- [docs/design-system.md](../design-system.md)：补充「设置 → 外观」中的语言设置项及英文核心术语约定。

### 验收清单

1. **Rust 单测**：`LocalizedText` 的 `Plain` / `Map` 序列化与反序列化、`resolve()` 完整回退链、`schema.rs` 解析多语字典与单语字符串的回归测试全部通过。
2. **TS 单测**：`zh-CN` / `en` 词典键集合与 `{param}` 占位符一致性测试、`resolveLocalized` 测试、斜杠命令按出版语言生成片段测试通过；`nsh check` 与 `nsh test` 全绿。
3. **人工视觉与交互验收**：
   - 以 `LANG=en_US.UTF-8` 与 `LANG=zh_CN.UTF-8` 启动，验证默认「跟随系统」准确识别；
   - 在「设置 → 外观」切换语言，验证导航、题库、比赛、工作室、属性抽屉（含 `olymp-classic` / `cnoi-classic` / `minimal` 动态 schema 控件）、`Cmd+K`、`/` 斜杠菜单、快捷键弹窗、关于页、窗口标题即时更新且无布局抖动/文字截断；
   - 在英文比赛与中文比赛中分别触发 `/hint`、`/interaction`、`/subtasks`，确认插入文本跟随出版语言；
   - 验证重启后语言偏好持久保留。
