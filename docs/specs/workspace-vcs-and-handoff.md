# Spec：极简领域化 Git 与离线盲验流转

> 状态：已确认（2026-11-28，`/grill-me` 深度对齐）
> 关联文档：[product.md](../product.md)、[architecture.md](../architecture.md)、[multi-author-workspace.md](./multi-author-workspace.md)、[roadmap.md](../roadmap.md)、[design-system.md](../design-system.md)

## 1. 背景与原则

在 [multi-author-workspace.md](./multi-author-workspace.md) 中，XCPC Workstation 确立了「开放目录、单一工作区模型、多人 Git 协同」的边界。但在实际使用中，将版本管理**完全抛给命令行 Git** 会造成明显的体验断层：

- 个人整理题库或小团队协同出题时，需要频繁切到终端做 `status` / `diff` / `commit` / `pull` / `push`，且原始文件级列表缺乏「题目 / 比赛」语义；
- 赛前邀请外部验题人**盲验（防剧透）**时，缺乏一键剥离题解、标程与数据的无剧透导出闭环；偶发需要外部出题人独立交题时，也缺少安全的单题目录导入入口。

同时，我们在讨论中明确**拒绝**将 Git 复杂化或把桌面端做成半个 GitHub/Polygon：不引入自建协作服务端、跨仓上游同步协议、双仓盲验同步、成员表与 `CODEOWNERS` 生成，也不在应用内重造分支管理与三方冲突编辑器。

核心设计原则：

1. **零新增配置字段**：不改动 `workspace.toml`、`problem.toml`、`contest.toml` 的 schema。
2. **零新增主导航**：不增加左侧一级空间，版本入口克制嵌入顶栏与工作室上下文。
3. **零 C 依赖与透明共存**：底层为系统 `git` CLI 的轻量 wrapper，与终端 `git` / `jj` 100% 行为一致。
4. **承认本地工具边界**：聚焦服务「个人题库 + 互信小团队」，将多角色硬隔离收敛为极薄的「盲验包导出 + 单题目录导入」。

## 2. 底层架构：`crates/xcpc-vcs`

### 2.1 为什么用系统 `git` CLI 轻量 wrapper

- **原生认证零踩坑**：直接复用用户本机 OpenSSH 配置（`ProxyJump`、`ssh-agent`、硬件密钥）、Windows Git Credential Manager (GCM)、系统钥匙串、`gh auth`、HTTP 代理、`.gitconfig` 与 hooks。
- **跨平台构建零负担**：不引入 `libgit2`（`git2`）或 `gix`，不增加 C 依赖，不影响 Linux → Windows（`cargo-xwin` + `+crt-static`）静态交叉编译与 UPX 单文件体积。
- **性能充分**：XCPC 工作区通常为数十至数百个文本文件，`git status --porcelain=v2 -z`、`git log`、`git show` 均在 5–20ms 量级，后台异步执行无感。
- **工具链探测复用**：沿用「设置 → 工具链」探测本机 `git` 路径（支持用户覆写与缺失时的平台安装指引，与 `g++` 体验一致）。未安装 `git` 时版本管理入口优雅降级，不影响其余功能。

### 2.2 领域化路径归组

Core 将 `git status --porcelain=v2 -z` 与 `git log --name-status` 的路径按工作区目录约定归组为领域实体：

| 路径前缀 | 领域分组 | 展示标识 |
| :--- | :--- | :--- |
| `problems/<slug>/...` | 题目 | 读取内存索引中的题目标题（回退 `<slug>`） |
| `contests/<id>/...` | 比赛 | 读取比赛名称（回退 `<id>`） |
| `templates/...`、`assets/...`、`workspace.toml` | 模板与配置 | 按相对路径展示 |
| `training/...` | 训练记录 | `training/logs.jsonl` |
| 其他路径 | 其他 | 按相对路径展示 |

### 2.3 安全与只读约束

- 所有读写操作严格限定在当前工作区根目录对应的 Git 仓库内；
- 遵守工作区 `--read-only` 守卫；
- **安全历史恢复**：将单题或单文件恢复到历史 commit 时，通过 `git show` / `git archive` 读取对象并**原子写回工作区**作为未提交改动（绝不执行 `git reset --hard` 或丢弃未提交工作），随时可撤销；
- **尊重冻结比赛**：对已冻结比赛的目录恢复历史前，仍遵守 Core 的冻结只读守卫（或明确拦截提示先解冻）。

## 3. 极简主干闭环（GUI 交互与核心操作）

### 3.1 界面入口（零新增主导航）

1. **顶栏右侧「版本状态胶囊」**：
   - 平静展示当前分支名、未提交变更数与远端领先/落后计数（如 `main · 3 · ↑1 ↓2`；全部干净且同步时仅淡色展示分支名）。
   - 非 Git 工作区时低调提供「启用版本管理（`git init`）」入口；未检测到 `git` 时仅在点击后引导至「设置 → 工具链」。
   - 点击胶囊展开锚点浮层「版本面板」（变更归组、提交、同步、远端配置）。
2. **单题 / 比赛工作室「历史」入口**：
   - 在单题与比赛工作室内就地打开当前题目/比赛的提交历史抽屉或弹窗，按时间倒序列出涉及该对象的提交，点击即用 `DiffView` 查看源码差异并可一键安全恢复。
3. **冷启动与工作区切换**：
   - 品牌页与工作区切换菜单新增「从 Git 仓库克隆」：输入仓库 URL 与本地目标目录，异步克隆并在完成后直接打开工作区。

### 3.2 隐藏暂存区双栏的归组提交

- 版本面板**不展示「暂存 / 未暂存」双栏**（类似 GitHub Desktop 交互），只呈现按「题目 / 比赛 / 模板与配置 / 其他」折叠归组的变更列表。
- 支持整题勾选或展开勾选单个文件；点击任意文件可在 `nsh/base` 的 `DiffView` 中查看行级源码差异。
- 根据勾选范围自动生成可编辑的中文/简洁提交说明（例如 `更新「Two Sum」题面与样例` 或 `更新 2 道题目与 1 场比赛`）。
- 提供「提交」与「提交并同步」动作：底层仅对勾选路径执行暂存与提交（未勾选的改动安全保留在工作区）。

### 3.3 后台静默感知与主干同步

- **低频静默后台 `fetch`**：打开已配置远端的 Git 工作区时及每隔 5 分钟（可在「设置 → 工作区」关闭）后台静默执行 `git fetch --no-tags`，**绝不改动工作区文件**，成功静默无弹窗，仅平静更新顶栏胶囊的 `↑N ↓M` 计数；离线或网络失败时静默降级，不打扰写作。
- **显式同步（Sync）**：
  - 所有 `pull` / `push` 均由用户主动触发；
  - 默认执行 `git pull --rebase` + `git push`；若本地存在未提交改动，先引导用户提交后再同步（不做静默 `autostash` 避免状态混乱）；
  - 未配置 `remote` 时，在版本面板内提供简洁的「关联远程仓库（URL）」输入。
- **轻量冲突兜底**：
  - 若 `pull --rebase` 遇到合并冲突，版本面板明确切换为冲突提示态，列出冲突文件路径；
  - 提供两个清晰动作：**「打开冲突文件」**（在应用或外部编辑器手动处理）与 **「中止同步」**（执行 `git rebase --abort` 安全回到同步前状态），不在应用内构建复杂的三方合并编辑器。

### 3.4 交互与流畅感规范

- 遵循 [design-system.md](../design-system.md) 与 [phase-6g-motion.md](./phase-6g-motion.md)：
  - 耗时 `< 150ms` 的本地查询（`status` / `log` / `diff`）不显示 loading；
  - 克隆、推送、拉取等网络耗时操作使用单槽右下角 Toast 或面板原位进度反馈；
  - `notify` 监听工作区与 `.git/HEAD`、`.git/refs/` 变更，外部终端执行 `git` / `jj` 后胶囊状态自动刷新。

## 4. 极薄离线流转（盲验防剧透与单题目录导入）

面向竞赛命题中「盲验防剧透」与「偶发外部出题人硬隔离交题」两个高频场景，不引入跨仓协议或新增配置，仅提供两项极薄的离线流转能力（归属 `crates/xcpc-packages`）：

### 4.1 导出盲验包（Blind Testing Bundle，ZIP）

- **设计目标**：让外部盲验人模拟参赛选手完整做题，物理上**零剧透**。
- **包内结构**（严格白名单）：
  ```text
  <比赛标题>-盲验包.zip
  ├── <比赛标题>-试题册.pdf          # 由 xcpc-engine 编译，与正式出版一致
  └── samples/
      ├── A/
      │   ├── 01.in
      │   └── 01.ans
      ├── B/
      │   └── ...
      └── ...
  ```
- **严格脱敏规则**：
  - 样例目录严格按比赛题号（`A`、`B`、`C`……）命名，**不暴露内部题目 `slug`**；
  - 绝不包含 `problem.toml`、`statement*.md`、`editorial.md`、`solutions/`、`generators/`、`tests/`、`validator.cpp`、`checker.cpp`、`interactor.cpp`、`contest.toml`；
  - 遵循「动静分离」原则，直接编译题册 PDF 并打包当前生效样例（冻结比赛自动从 `snapshot/` 取材）。
- **入口与闭环**：
  - GUI：比赛出版工作室「导出 ▾」分体按钮菜单新增「导出盲验包（ZIP）」，同步接入 `Cmd+K`；
  - CLI：`xcpc export blind <contest-id> [-o <path>] [--json]`；
  - MCP：`export_blind_bundle`（写入工作区 `build/`，受 `--read-only` 限制）；
  - **代码回收**：盲验人完成后发回代码目录，直接对接现有「试跑验题人代码」完成全量评测与报告导出。

### 4.2 从 XCPC 题目目录导入

- **设计目标**：偶发需要外部出题人硬隔离单独出题时，出题人交来单题目录（`problems/<slug>/`），组题人可一键安全合入当前比赛工作区，不追踪血缘、不做跨仓同步协议。
- **核心规则**：
  - 校验源目录包含可解析的 `problem.toml`；
  - 严格拒绝符号链接逃逸与路径穿越（与 Polygon 导入共用路径安全校验）；
  - 原子复制到当前工作区 `problems/<target-slug>/`；
  - **冲突策略**：默认目标 `slug` 已存在时拒绝静默覆盖，提示用户指定新 `id` 或显式确认覆盖（覆盖前按常规写守卫检查，确保不影响已冻结快照）。
- **入口**：
  - GUI：题库顶部「+」分体导入菜单新增「从题目目录导入」（调起系统文件夹选择器），同步接入 `Cmd+K`；
  - CLI：`xcpc import dir <path> [--id <slug>] [--overwrite] [--json]`。

## 5. Core / CLI / MCP 边界

| 能力 | Core Crate | 桌面 GUI | CLI (`xcpc`) | MCP (`xcpc mcp`) |
| :--- | :--- | :---: | :---: | :---: |
| Git 状态、领域归组、历史、源码 Diff | `xcpc-vcs` | 全量 | 不重复包装 `git` | **只读开放**（`vcs_status`、`vcs_log`、`vcs_diff`） |
| Git 克隆、初始化、关联远端、提交、同步、冲突中止、安全恢复 | `xcpc-vcs` | 全量 | 不重复包装 `git` | **明确禁止**（永远由人触发） |
| 导出盲验包（ZIP） | `xcpc-packages` | 导出菜单 / `Cmd+K` | `xcpc export blind` | `export_blind_bundle`（受 `--read-only` 限制） |
| 从 XCPC 题目目录导入 | `xcpc-packages` | 题库导入菜单 / `Cmd+K` | `xcpc import dir` | 按需后续评估（一期不做） |

## 6. 明确不做

- **不做 `libgit2` / `gix`**：坚持系统 `git` CLI wrapper。
- **不做分支管理 UI**：仅平静显示当前分支名，切/建/删分支交给终端 `git` / `jj`。
- **不做应用内复杂三方冲突合并编辑器**：遇冲突仅列出文件并提供「打开冲突文件 / 中止同步」。
- **不做历史版本 PDF 渲染视觉 Diff**：历史对比仅做源码文本 `DiffView`。
- **不做 Git 托管平台集成**：不调 GitHub / GitLab / Gitea API，不做应用内 PR 评论流，不解析远端 URL 跳网页提 PR。
- **不做重型多角色协作协议**：不做自建协作服务端、账号/权限体系、实时 CRDT、一题一仓上游同步协议、独立盲验 Git 仓、成员表 `[members]` 与 `CODEOWNERS` 自动生成。
- **不新增任何工作区/题目/比赛配置文件字段**。

## 7. 分步实施与验收清单

### 实施顺序

1. **Step 1（`crates/xcpc-vcs` + 只读 MCP + 桌面端极简主干闭环）**：
   - 实现 `xcpc-vcs`（`git` 工具链探测、状态与领域归组、克隆/初始化/远端关联、归组提交、`fetch`、主干同步与冲突中止、单题/比赛历史与源码 Diff、原子安全恢复）；
   - 接入 `xcpc-mcp` 三个只读工具（`vcs_status`、`vcs_log`、`vcs_diff`）；
   - 桌面端补齐「设置 → 工具链」`git` 探测、品牌页「从 Git 仓库克隆」、顶栏版本状态胶囊与版本面板、工作室历史 Diff 视图与低频后台静默 `fetch`。
2. **Step 2（`crates/xcpc-packages` 极薄离线流转）**：
   - 实现盲验包脱敏导出（Core + CLI + MCP + 比赛导出菜单）；
   - 实现从 XCPC 题目目录导入（Core + CLI + 题库导入菜单）。

### 验收剧本

1. 品牌页「从 Git 仓库克隆」拉取一个测试工作区并自动打开；顶栏胶囊显示当前分支且无未提交改动。
2. 修改 2 道题的题面与样例，打开顶栏版本面板：变更按两道题清晰归组，仅勾选其中 1 道题，编辑自动生成的提交说明并点击「提交」；另一道题的改动安全留在工作区。
3. 在单题工作室内打开「历史」，用 `DiffView` 对比前后版本，点击恢复到旧版本，确认旧内容以未提交改动写回工作区且未破坏 Git 历史。
4. 外部远端推送新提交后，静默 `fetch` 使顶栏胶囊出现 `↓1`；有未提交改动时点击同步被引导先提交；提交后一键同步完成 `pull --rebase` + `push`。
5. 制造同文件同处冲突并同步：版本面板列出冲突文件，点击「中止同步」后工作区无损回到同步前状态。
6. 在比赛工作室点击「导出 ▾ → 导出盲验包（ZIP）」：解压确认仅有 `试题册.pdf` 与按题号命名的 `samples/A/...`，零题解、零标程、零测试数据、零内部 slug。
7. 在题库「+」菜单选择「从题目目录导入」，验证合法题目成功合入、slug 冲突时拒绝静默覆盖、含符号链接逃逸时报错拦截。
