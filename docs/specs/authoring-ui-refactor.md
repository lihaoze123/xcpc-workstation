# Spec：出题与比赛检查界面收敛（Phase 3 界面收敛）

> 状态：已确认（2026-11-24，`/grill-me` 逐项确认）
> 关联文档：[roadmap.md](../roadmap.md)、[design-system.md](../design-system.md)、[phase-3c-interactive-communication-subtasks.md](./phase-3c-interactive-communication-subtasks.md)、[phase-3d-contest-readiness.md](./phase-3d-contest-readiness.md)、[local-polygon.md](./local-polygon.md)
> 附录（评审证据与截图）：[../review-phase3-ux.md](../review-phase3-ux.md)

## 1. 背景与目标

Phase 3A–3D 的功能链路已经跑通，但 2026-11-24 的实机评审（linux-cua）发现，桌面端的出题与比赛验题界面是按实现者的心智组织的：

1. **出错时不说原因**：没有编译器、自测缺失等最常见的失败，界面只显示「操作没有完成」或残缺的检查项标题；
2. **术语直接搬上界面**：UB、阻断 / 预警、验收过期、验题人目录、% TL、min / sum、收编进 solutions/、interactor、sol:std 等，出题人看不懂；
3. **入口和状态多头**：同一动作有 2–3 个入口，同一状态有 6 种叫法；比赛里不能检查单题，修题要跳出比赛；
4. **比赛验题体检页杂乱**：两层顶栏、4 个按钮、7 列表格、与表格重复的风险卡片、矩阵和清单重复的验题人卡片、两列彩色胶囊加红边条，字号和颜色都不走 Token。

本次收敛**不新增功能**，只重组结构、统一用词、补齐出错反馈。原则是 AGENTS.md 中的「做减法」与 design-system §6.5 / §7 / §9.1。

## 2. 统一词表

全应用（GUI、CLI 中文输出、Core 的 `human_message`）只用下表中的说法。规格文档中的内部称呼（verify、strict、sanitize、audit、package）不出现在界面上。

| 概念 | 界面说法 | 不再出现 |
| :--- | :--- | :--- |
| 跑全部数据与解法并签发通过（内部 `--strict` / `verify`） | **检查**（单题与比赛同一个词） | 验证、验收、严格验收、构建 |
| 题目状态 | **未检查 / 有问题 / 已通过** | 未验证、未构建、已过期、验收失败、数据异常、数据未验、可用于比赛、已验收 |
| 比赛整体可交付 | **可以定稿** | 可定稿、存在待处理项、阻断、预警、阻塞项 |
| Sanitizer（ASan / UBSan） | **内存检查**；结果「没有发现内存问题」 | UB 体检、整场 UB 体检、放宽时限 5000ms |
| 外部提交 | **验题人代码**；动作「试跑验题人代码…」 | 外部解法、验题人目录、多验题人横向矩阵 |
| 把外部代码写入题目 | **加入解法** | 收编、收编进 solutions/ |
| `solutions/`、`[[test]]` 等 | **测试数据**（侧栏分组名照旧：解法、生成器、测试数据） | 题目包、package |
| 子任务计分 `min` / `sum` | **全对才得分 / 按通过比例得分** | 捆绑测试（min）、按点均分（sum） |
| 部分分解的预期得分 | **应得分数** | 得分断言 |
| ILE | **卡住了（未刷新输出或协议死锁）** | 仅写 ILE |
| 与标程用时之比 | **与标程相近 / 比标程慢 N 倍**（仅在 ≥ 2× 时写倍数） | `1.00× std` |
| 导出 Markdown 报告 | **导出检查报告** | 导出 Markdown、导出体检报告 |

**英文界面**同步：Check / Not checked / Has issues / Passed / Ready to finalize / Memory check / Tester code / Add as solution。

**不改的部分**：CLI 命令名与已有参数（`xcpc package build --strict`、`--sanitize`、`xcpc contest audit`）、MCP 工具名与字段名、结构化错误码。它们面向脚本和 Agent，稳定优先。`skills/xcpc-problem-creator/` 继续用技术词，但凡是教 Agent 向用户转述结果的段落，要用本词表。

## 3. 状态表示

### 3.1 题目状态标记

题目状态在左侧题目列表（比赛工作室大纲、题库表格「状态」列）与出题面板工具行中，用同一个固定宽度的标记表示：

| 内部状态 | 标记 | 悬停 / 浮层说明 |
| :--- | :--- | :--- |
| 未构建、已过期（`stale`、`unbuilt`） | 灰色空心圆 | 「还没检查」/「改动后还没重新检查」 |
| 检查失败、内存检查发现问题、缺自测等 error 级问题 | 红点 | 第一个问题的一句话说明，例如「校验器缺少无效用例」 |
| 已通过 | **很淡的勾**（弱化文本色） | — |
| 纯题面题（无测试数据） | 不显示 | — |
| 批量检查进行中 | 原位转圈 | — |

warning 级问题（时限余量紧、数据过大、缺独立参考解等）不改变标记，只出现在状态浮层里，并附一个淡色「提醒」小节。

### 3.2 状态位与状态浮层

- 出题面板工具行（单题）与比赛工作室标题栏（比赛）各有**一个**固定宽度的状态位，内容是：标记 + 一句话（例如「2 题有问题」「1 题未检查」「可以定稿」「没有找到 C++ 编译器」）。
- 点击状态位打开**状态浮层**，逐条列出问题，每条包含：白话原因、所在题目（比赛时）与「前往」。点击「前往」直接打开该题的出题面板并定位到对应对象（校验器、某个格子、子任务等）。
- 「复制详情」只放在状态浮层里。

## 4. 比赛工作室：取消独立的验题体检页

- **删除**比赛工作室的「题面 | 验题体检」分段与 `ContestReadinessView`。
- 比赛工作室左侧大纲（封面、A、B、C…）每题加上 §3.1 的状态标记。
- **选中某题后，右侧提供「题面 | 出题」两个 Tab**；「出题」复用单题的出题面板组件（§5），可以就地修改、就地检查。比赛里不再需要跳到单题工作室。
- **标题栏**：比赛名 + 状态位（§3.2）+「检查 ▾」描边按钮 +「导出 PDF ▾」主按钮（主按钮位不变）+ 面板开关。
  - 「检查」：检查所有未检查和有问题的题；
  - ▾ 下拉：「全部重新检查」「检查内存问题」「试跑验题人代码…」「导出检查报告」。
- **批量进度**：不插入进度条，也不推动布局。每题状态标记原位转圈，「检查」按钮原位显示「检查中 2/4」，并在同一位置提供取消。部分失败时，对应题目原位变成红点，结束后状态位汇总。
- **原体检表的指标**（标程最慢占时限、数据体积与累计耗时、错解与自测覆盖、内存检查、lint 告警数）下沉为单题出题面板「检查结果」中的信息，或以 warning 形式进入状态浮层。不再有整场七列表格。整场汇总只出现在「导出检查报告」生成的 Markdown 里。
- **在比赛里检查一道题，使用比赛覆写后生效的时限与内存**；单题工作室仍按 `problem.toml` 的限制。浮层写明依据，例如「在本场 1 秒时限下，标程最慢 0.8 秒（80%）」。Core 的 `audit_contest`、比赛内的检查与定稿前的检查都读取比赛覆写。
  - 覆写改变了时限或内存时，比赛内的检查是一次独立的检查：通过记录单独保存（`build/problems/<slug>/verified_report.t<毫秒>-m<KiB>.json`，哈希里带上生效的限制），既不覆盖题库里的「已通过」，也不会被它冒充；没有覆写或覆写值相同则共用同一份记录。
  - CLI `xcpc package build <id> --strict --contest <比赛>` 与 MCP `build_package` 的可选字段 `contest` 用于在比赛时限下检查；`xcpc contest freeze` 的提示会在需要时带上 `--contest`。
- 属性抽屉（面板开关）作为浮层打开时，不得遮挡、截断工具行按钮；当前选中题的设置只在「题面」Tab 下出现。

### 4.1 验题人代码

- 「试跑验题人代码…」先弹出一句说明：「选择一个文件夹：按题号或题目名放代码（A.cpp、B.cpp），多位验题人可各占一个子文件夹」，再调起目录选择器。
- 结果**拆回到各题**：每题出题面板侧栏「检查结果」下出现「验题人代码 (N)」，内容是单题外部试跑结果表，增加一列「来自」（验题人名）；「加入解法」为行悬停时出现的图标按钮。
- 比赛状态浮层里增加一小节汇总，例如「验题人代码：alice 有 2 题未通过（B、D）」，点击跳到对应题。
- **不再在界面上画「验题人 × 题目」矩阵**；矩阵只出现在导出的检查报告里。
- 结果只保留到应用关闭为止，不写入工作区（零污染，与 phase-3d §3.2 一致）。

## 5. 出题面板（单题与比赛共用）

### 5.1 分层：标题栏管对象，面板工具行管题目动作

- **窗口标题栏**：
  - 单题工作室：题名 +「题面 | 出题」+ 面板开关；
  - 比赛工作室：见 §4。
- **出题面板工具行**（38pt，与编辑器「题面 / 样例 / 题解」行同高同构）：
  - 左：本题状态位（§3.2）；
  - 右：「检查 ▾」主按钮。下拉项：「只运行选中的测试 / 解法」「检查内存问题」「试跑外部代码…」。
- **筛选不再是按钮**：在矩阵上点列头、行头即可勾选；有选中项时，主按钮文案变成「运行选中」。
- 局部运行完成后的原位轻确认沿用 design-system §6.5 第 3 层（`✓ 完成`）。

### 5.2 侧栏

- 第一项 **「题型」**，右侧淡字摘要，例如「传统」「交互 · 两轮 · 子任务 100 分」。点开后是题型设置页，三个控件：
  - **评测方式**：标准比较（内置检查器）/ 自定义检查器 / 交互（选交互时自动创建 `interactor.cpp`，含 flush 示范）；
  - **运行轮数**：1 / 2 / 3…（≥ 2 时说明「上一轮的输出作为下一轮的输入」，写入 `[package].runs`）；
  - **计分**：整题对错 / 按子任务计分（后者才出现子任务列表）。
- **按题型显隐**：
  - 交互题显示「交互器」；只有另配了 checker 时才显示「评测器」；
  - 非子任务题不显示「子任务」；
  - 去掉侧栏右侧的暗码（`interactor`、`checker.cpp`、`×2`）。
- **去掉矩阵上方的题型徽标行**。
- **侧栏底部不再有「UB 体检」「试跑外部解法」入口**。它们只作为结果出现：有结果时，「检查结果」组下多出「内存检查」「验题人代码 (N)」。
- 解法行右侧统一显示预期：「应 AC」「应 WA」「应得 30 分」「应得 60–70 分」。
- 自测计数必须包含 `tests/validator/{valid,invalid}/<子任务>/` 子目录（修复当前 `crates/xcpc-judge/src/ops.rs` 只列顶层的问题）。

### 5.3 评测矩阵

1. **颜色只表达「不符合预期」**：
   - 符合预期：AC 用主文本色，其他结果用次级文本色，无底色；
   - 不符合预期：rose 12% 浅底 + 红字（design-system §3.2），不用实心色块；
   - 「仅看异常」只统计不符合预期的格子。
2. **去掉「结论」行**：每个解法的结论放在列头。符合预期不加标记，不符合时加红点，悬停说明「应 AC，实际 WA」。
3. **「总分」只在子任务题出现**，作为列头第二行淡字（「30 / 100」）。子任务分组行只写得分（「35 / 70」），不跟结果缩写。
4. **耗时**：TLE / ILE 显示墙钟时间，其余显示 CPU 时间；数字右对齐，使用 `tabular-nums`。
5. 样例分组命名为「样例」；没有子任务的题不分组。

### 5.4 诊断面板（点击格子）

1. 标题一行：符合预期时写结果的白话（例如「卡住了（ILE）」）；不符合时写「应 AC，实际 WA」（红字）。只有不符合预期时才出现解释框，内容是白话原因和排查方向。
2. 「交互器信息」与「评测器输出」合并为「判定说明」；只有两者都存在且内容不同时才分开。
3. 交互日志：去掉行底色，只给箭头着色，左侧细色线区分方向；上方一行图例「→ 交互器发给解法　← 解法的输出」；多轮时按轮分组，小标题「第 1 轮」，去掉逐行的 `#1`。
4. 元信息行写「测试 1　std　2 ms　3.9 MB」（间距分隔，不用 `·`，不用 `#1`）；判定说明与生成命令放在日志之上，日志占满剩余高度。

### 5.5 子任务

- 列表卡片保留，计分方式写「全对才得分 / 按通过比例得分」，依赖写「依赖：子任务 1」（全角冒号）。
- 编辑对话框：去掉复述字段的副标题；计分方式与前置依赖的选中态统一为 `--bg-selected` 浅灰（design-system §3.1）。
- 空状态只保留一个「添加子任务」按钮（design-system §9.1 第 5 条）。

### 5.6 内存检查与外部代码结果

- 内存检查通过：只显示一行「没有发现内存问题」（成功静默，§6.5）；有问题时才列出明细，明细里用对象名（「标程 std」「生成器 gen_n」「校验器」），不出现 `sol:` / `gen:` 前缀、`runs` 和放宽后的毫秒数。
- 外部代码运行中，只在触发控件原位显示进度，不在三处同时显示「正在试跑…」。
- 外部代码结果表：「判定 / 通过 / 最慢用时 / 与标程相比」；「加入解法」为行悬停图标按钮。

## 6. 出错与环境缺失

1. **提前告知**：应用启动时与「重新检测」后，记住编译器探测结果。探测不到时：
   - 题目状态位与比赛状态位直接显示「没有找到 C++ 编译器」+「去设置」，点击直达 设置 → **工具链**（当前错误地落在「工作区」页）；
   - 「检查」按钮**不置灰**；点击后展开同一说明浮层，不发起运行。
2. **错误文案全部取自 Core**：GUI 直接显示 Core `human_message`（中文三段式）。`apps/desktop/src/ui/logic.ts` 的 `errorCopy` 只保留文件冲突等界面自身的情况。执行类操作不允许落到 `error.generic`（「操作没有完成」），并加单测兜底断言。需要覆盖的 judge 错误码至少有：`no_compiler`、`compiler_not_found`、`no_main_solution`、`multiple_main_solutions`、`unknown_checker`、`test_not_found`、`generator_not_found`、`solution_not_found`、`invalid_limit`、`invalid_config`。
3. **出错不插横幅**：错误显示在触发控件对应的状态位里（固定高度、零位移）；「复制详情」在状态浮层里。
4. **检查失败的原因必须是具体原因**，不能是检查项标题（当前体检页显示「Validator 存在与自测」）。
5. **工具链页**：安装命令渲染为可一键复制的代码块；按当前系统只显示对应发行版的命令（含 Nix 写法）；「PATH」「XCPC_CXX」「-O2」收进「高级」折叠项。
6. 新工作区未检查的题，不在题面预览 HUD 里算作「错误」。未检查不是题面问题，Preflight 只报题面本身的问题，测试数据的状态由 §3 的状态位负责。

## 7. 视觉工艺（默认执行）

- 颜色一律使用 design-system Token（`--destructive`、§3.2 状态色等），删除组件内写死的 rgba / 十六进制值（当前 ContestReadinessView 22 处、BuildConsole 40 处、BuildDetailPane 7 处）。
- 出题相关组件的字号收敛到 12 / 13 / 14 三档（当前混用 10.5–14 共 7 种）；数据表格行高 36–40px；数字一律 `tabular-nums`。
- 代码编辑器（检查器、交互器、解法等 C++ 源码）默认关闭连字，避免 `!=` 显示成 `≠`。
- 不用实心大色块表达状态；同一元素只用一种编码（标记或颜色，二选一），不再叠加左侧红边条、彩色胶囊和红色图标列表。

## 8. CLI

- `xcpc` 的人类可读中文输出改用 §2 词表（例如 `xcpc contest audit` 输出「2 题有问题」「可以定稿」，不再写「验题体检」「存在阻塞项」「Sanitizer」「package_stale」）。
- `--json`、MCP 字段与错误码不变。

## 9. 实施顺序

每步都可以单独提交：

1. **Core**：词表文案与 `human_message`；比赛覆写时限下的检查；自测子目录统计修复。
2. **出错反馈**：状态位与状态浮层组件；编译器预检；「去设置」落点；工具链页。
3. **出题面板重构**：工具行、题型条目与显隐、矩阵规则、诊断面板、子任务与内存检查收敛。
4. **比赛工作室**：嵌入出题面板；删除 `ContestReadinessView`；「检查 ▾」与批量原位进度；验题人代码拆回各题。
5. **CLI 中文输出**改用新词表；同步 `skills/xcpc-problem-creator/` 中的转述段落。

## 10. 不做

- 不新增检查维度或报告字段；
- 不在界面上提供「验题人 × 题目」矩阵；
- 不改 CLI 命令名、MCP 工具名与错误码；
- 不在比赛层面保留任何整场指标表格。
