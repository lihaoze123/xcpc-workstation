# 界面设计系统

本文定义 NSH 应用界面的信息架构和视觉语言。组件**以 `nsh/base` 为基础**（需要时可以基于 NSH 自己写组件，不引入第三方 UI 组件库），主题通过 `nsh/base` 的主题/Token 机制实现；[`hero-nsh`](https://c-w-xiaohei.github.io/hero-nsh/)（HeroUI 风格）只作样式参考，不作为依赖。快捷键写作 `Cmd`，在 Linux 上对应 `Ctrl`。题面纸张的样式见 [statement-style.md](./statement-style.md)。色板和布局骨架可以在 [`reference/color_system_preview.html`](./reference/color_system_preview.html) 中交互式查看。

## 1. 设计理念

整体风格是**现代极简的「精密工具」风**，融合 Linear / Zed / Craft 的精密感和 HeroUI 式的柔和层次（柔和圆角、细腻的边框和层次投影、克制的高对比排版）。

1. **内容优先，界面退让**：界面本身用低饱和的中性灰，不与纯白的 A4 题面纸张和算法语义色争抢注意力。
2. **精密与克制**：用 1px 清晰边框建立结构秩序，用微圆角和极轻的投影化解生硬感；所有数字严格等宽对齐（`tabular-nums`）。
3. **高频操作无阻碍**：动效时长 120–180ms，绝不拖慢键盘操作和实时排版校对。
4. **让布局说话（Layout Over Labels）**：空间位置和排版形态本身能表达含义的地方，就不再叠加多余的标题和解释文案；严禁在界面上暴露开发者实现细节和无意义的技术指标（见 §7）。同理，不用 `·`、`|` 这类分隔符和装饰性的分隔线来隔开并列的内容，交给间距和对齐（界面和出版物都如此；题面册继承自基准的页眉页脚横线除外）。

## 4. 材质、圆角与层级

- **结构分割**：大纲、编辑器、预览区和出版开关面板之间只用 **1px `--border-subtle` 细实线**分割，不加外阴影。
- **圆角梯度**：

  | 元素 | 圆角 |
  | :--- | :--- |
  | 徽章 / Tag / 键帽 | `4–6px` |
  | 按钮 / 输入框 / 列表选中项 | `6–8px` |
  | Bento 卡片 / 题面分卡 / 弹窗 | `10–12px` |
  | 预览区悬浮胶囊 HUD | `9999px` |

- **嵌套圆角要同心**：`内圆角 = 外圆角 − 内边距`。例如卡片圆角 `12px`、内边距 `4px`，那么内部的选中项或按钮圆角是 `8px`。
- **立体层次**：普通卡片用 `1px` 细边框加极轻的环境阴影 `0 1px 2px rgba(0,0,0,0.03–0.04)`；强投影只留给拖拽替身与模态弹窗。浮层（`Cmd+K` 命令面板、下拉菜单、抽屉、悬浮胶囊 HUD）用轻度毛玻璃（`backdrop-blur: 12px`）加半透明背景，并在暗色模式下叠加 `1px` 提亮内描边（`sheet-rim: rgba(255,255,255,0.12)`），在 Linux 上比单纯依赖重模糊更稳定分层。
- **统一自绘窗口顶栏**：采用 `TitleBarStyle::Hidden` 并为顶栏及弹窗背景蒙层设置 `.window_drag(true)`，左右留出窗口安全区，确保打开弹窗或浮层时窗口拖动依然不被锁死。

## 5. 字体排印与信息密度

- **UI 字体**：西文优先 `Inter`（可随应用打包），其次是系统无衬线字体；中文依次匹配 `Source Han Sans SC` / `Noto Sans CJK SC`。
- **代码、样例和源码编辑**：优先 `JetBrains Mono` / `Maple Mono` / 系统等宽字体，连字开关可以配置。
- **数字**：Rating、时空限制、题号计数、页码和表格统计一律使用 `font-variant-numeric: tabular-nums`。
- **密度标尺**（参照 Linear 的默认值）：

  | 元素 | 规格 |
  | :--- | :--- |
  | 页面主标题 | `18–20px` SemiBold |
  | 卡片 / 区块标题 | `14px` Medium |
  | 常规正文与列表 | `13–14px` Regular，行高 `1.45` |
  | 数据表格行高 | `36–40px` |
  | 辅助元信息 / 状态栏 | `11.5–12px` |

## 6. 关键界面

### 6.1 训练总览（Bento Grid）

采用响应式 Bento Grid，卡片间距 `12–16px`，不加多余的副标题和技术指标：

- **顶部概览条**：已绑定的 OJ 平台和实时 Rating 徽章（按难度色阶着色），以及今日 / 本周 / 本月 / 累计 AC 和待补题的大号 `tabular-nums` 数字卡。
- **双模式跨年热力图**：右上角用轻分段控件切换 `提交 | AC`，右侧是年份快捷切换（`2026 / 2025 / 2024`）；方块用 5 阶鸭青蓝（`H:195°`）或经典 Emerald 渐变，Hover 时显示当天明细。
- **刷题画像**：能力雷达图（主色半透明填充，坐标网线清晰）、平台过题环形图、难度分布柱状图（使用难度色阶，**点击柱子可以直接筛选对应区间**）、可滚动的标签 AC Top 横向进度条、跨平台近期提交时间线。
- **待补题与复盘队列**：紧凑行表（`36–40px`），显示难度色标、题名和来源，并提供一键「收入精选题库 / 补题」入口。

### 6.2 出版工作室预览画布

- **画布**：使用 `--bg-paper-stage`，视觉上完全退后。
- **A4 纸张**：始终显示为纯白（`#FFFFFF`），带双层纸张投影（近处细描边 + 远处柔和扩散）和 `1px` 极淡的纸边。只有单页模式。支持缩放和平移（触控板双指无级缩放）；`Ctrl+点击` 页面跳到编辑器里对应的源码行。
- **底部悬浮毛玻璃胶囊 HUD**：居中，距画布底部 `16px`，包含以下控件：
  `[ - | 100% | + | 适合宽度 ]`、`[ ‹ 3 / 12 › ]`、`[ Preflight 状态徽章 ]`（无问题时不显示）。HUD 常驻，不自动淡出。

## 7. 文案克制规范

1. **靠视觉自我解释，去掉冗余标签**
   - 空间位置和排版形态已经能说明功能的区域（左侧题目列表、中间编辑区、右侧纸张预览、热力图方块等），**不加区块标题或括号说明**。例如不要写「结构化编辑器」「比赛大纲」「题目描述 (Legend)」。
   - 成功状态保持静默：编译正常、校验通过、保存成功时，不显示「编译成功 / Linter 通过 / 已保存」之类的徽章。**只在出现错误、警告，或耗时超过感知阈值（> 200ms）时**才温和地给出提示。
2. **不泄露技术实现**
   - 主工作区里**禁止出现**底层技术名词、配置文件名和工程遥测指标，例如 `SQLite FTS5`、`增量编译 12ms`、`theme.toml`、`MCP Ready`、`NSH Canvas`。
   - 这些信息统一放到「设置 → 开发者 / 高级 / MCP 集成」二级页面，按需查看。主工作区只使用竞赛选手和命题人熟悉的领域语言。

## 8. 动效与流畅感（Fluidity）

整体手感基调为 **Linear / Zed 精密工具风**：零弹跳过冲，采用临界阻尼或指数缓动（`120–160ms`），**所有动效随时可被打断**，绝不拖慢键盘操作、编辑器输入和连续手势。

| 场景 | 时长 | 缓动 | 约束 |
| :--- | :--- | :--- | :--- |
| 按钮 Hover / 聚焦 / 切换 | `120ms` | `cubic-bezier(0.2, 0, 0, 1)` | 干脆，无拖影 |
| Tab 指示条 / 侧栏选中滑块 | `150ms` | `cubic-bezier(0.2, 0, 0, 1)` | 跟随流畅 |
| 面板收折 / 出版开关抽屉 | `150–180ms` | `cubic-bezier(0.16, 1, 0.3, 1)` | 优先 `transform` / `opacity`，不挤压编辑器重排 |
| `Cmd+K` / 弹窗显隐 | `140ms` | 缩放 `0.98 → 1` + 淡入 | 无弹簧过冲 |
| 拖拽排序（组卷 / 样例） | 实时跟手 | 目标位置显示细蓝线 | 松手后 `150ms` 归位 |
| `Ctrl+滚轮` 缩放插值 | `~120ms` | 指数阻尼（`1 - exp(-dt/32)`） | 光标锚点像素锁定，随时可被捏合/滚动打断 |

全局遵守系统的 `prefers-reduced-motion` 设置：开启时降级为瞬间切换或纯淡入淡出。

### 8.1 流畅感工程铁律（Compositor-First & Zero-Jitter）

以下规则作为桌面端 UI 实现的硬约束（与「不能有 1px 布局抖动」同级）：

1. **连续手势严格合成器优先**：缩放、平移、拖拽排序等高频连续手势期间，**只更新 GPU 合成器 `transform`（`translate` / `scale`）**，禁止每帧修改布局尺寸（`width`/`height`/`padding`）或反复调用 `scrollTo` 与布局竞态；手势结束时单次原子提交布局状态与滚动偏移。
2. **输入 1 帧内乐观响应（≤ 16ms）**：点击、切换 Tab、切题、键盘导航（`J/K`、`Cmd+1..4`、`Cmd+K`）必须在当前帧给出视觉状态变化，绝不等待磁盘 I/O、SQLite 查询或 Typst 编译返回才更新激活态；高频交互绝不阻塞编辑器打字。
3. **零闪白、零整树重建**：切换题目、切换「题面 / 题解」、筛选列表或重新编译时，保留旧画面（或列表滚动位置）直到新数据/新图层首帧就绪，**禁止先清空状态闪一下白画布**；动态列表必须稳定 `key`，复用已有视图。
4. **面板与浮层优先 `transform` + `opacity`**：侧栏、抽屉、浮层显隐避免逐帧改宽导致正文与编辑器文字反复折行抖动。
5. **可打断性**：任何程序化动画（如平滑跳页、滚轮缩放阻尼）一旦收到用户新的滚轮、捏合、拖拽或按键，必须立即终止并无缝接管当前位置，不与用户抢控制权。

### 8.2 纸面预览画布手感标准（Phase 2 补齐）

- **缩放**：两阶段合成器缩放（手势期纯 `transform` 锚定视口光标，离散滚轮做 ~120ms 指数阻尼，触控板捏合 1:1 跟手，结束时单次原子提交并清晰化分块）。
- **切题 / 切题解零闪白与视口记忆**：切换目标或「题面 / 题解」时保留旧页画面（至多轻度淡化）直到新首帧就绪，并按 `(target, id, book)` 记忆 `{ zoom, scrollY, panX }`。
- **比赛内按题号跳页**：同场比赛内点击 `A / B / C` 时直接使用 NSH 原生帧时钟 `scrollTo({ y, animated: true })` 做短时平滑滚动（可随时被手动滚轮打断）；跨比赛或单题切换则直接就位。
- **横向平移与拖拽轻惯性**：放大后使用嵌套横向 `<Scroll>` 获取原生横向惯性，边界柔和阻尼收住而非硬撞墙。

### 8.3 NSH 0.6 Linux 实践与避坑（参考 `gicek/safay`）

参考同栈 NSH 桌面产品 `gicek/safay` 的结构与交互打磨（保留本项目的深鸭青蓝 `H:195°` 色板、零装饰原则与成功态静默规范，不照搬其引导箭头、空态光环装饰及蓝色主色）：

1. **零抖动微交互**：
   - **聚焦环**：使用 `ring(1).ring_inset()`（纯阴影，占 `0px` 布局空间），绝不因边框切换撑宽或截断文字。
   - **分级按压反馈**：`.active()` 按元素面积做克制的微缩（卡片 `0.99`、侧栏行 `0.98`、常规按钮 `0.96`、图标按钮 `0.94`），零过冲。
   - **零重排悬停与错误占位**：行内操作放绝对定位浮层或预留固定槽位；表单与弹窗底部预留固定错误槽位（`status_line`），报错时高度不跳动。
   - **下拉框即时收起**：`Select` 触发重操作时用 `set_timeout(0)` 延后执行，让下拉菜单在当前帧立即收起。
   - **键盘与指针零冲突（搜索 / 列表）**：搜索框保持焦点同时用 `When::Always` 监听上下键移动高亮行，仅越出视口时最小 `reveal()`；指针高亮仅监听 `on_mouse_move`（不用 `mouse_enter`），避免键盘滚动时静止光标反抢焦点；高亮行相邻分割线自动隐藏。
   - **零重排拖拽排序（组卷 / 样例）**：`4px` 拖动阈值防误触；起拖时一次性 `measure()` 缓存槽位网格；仅浮起替身订阅高频指针信号（列表行不重绘）；槽位交换走 `180ms EaseOut`；松手保留乐观顺序（`pending` 标记）直到异步落盘完成，防止回弹闪跳。
2. **NSH 0.6 Linux（GTK4 / GSK）原生能力与避坑**：
   - **优先原生帧时钟动效**：`Animated`、`transition_opacity` / `transition_transform` / `transition_colors` 与 `scrollTo({ animated: true })` 直接跑在 GTK `GdkFrameClock` 上（零 JS 往返、天然可打断、自动遵守 `reduce_motion`）。
   - **桌面分栏**：可拖拽多栏使用 `<ResizablePanelGroup>`，**不用 `<SplitView>`**（iPadOS 固定分栏）。
   - **Linux 缩放约束**：`<Scroll zoomTo / maximumZoomScale>` 在 Linux 是空操作，继续使用两阶段 GPU `transform` 缩放。
   - **禁止重面板动画改宽**：不要对编辑器或预览区等重面板使用 `LayoutAnimation` / `animateLayout` 动画改宽（每帧 `queue_allocate` 会导致正文反复折行卡顿）；抽屉走 `transform: translateX()` 浮层滑入，固定侧栏 0ms 单帧切宽 + 内部内容 `120ms` 淡入微移；`animateLayout` 只用于小槽位交换。
   - **`<Scroll>` 内图片溢出保护**：`<Scroll>` 内的 `<Image>` 必须设置 `overflow: hidden`，防止原图像素尺寸被计入滚动范围。
   - **长列表与热刷新**：`Cmd+K` 与题库长列表基于 `<Command filterable={false}>`（接 Rust 内存模糊 + Frecency 排序）与 `<DataTable>`（行列虚拟化）；`notify` 热刷新时通过 `EditorRef` 原地更新并保留光标与滚动位置，禁止重建 `<Editor>`。

### 8.4 UI 改动自检清单

每次修改桌面端交互后，需在真机窗口（必要时开 `NSH_FPS=1`）核对：
- 连续手势（滚轮/捏合/拖拽）无抖动、无锚点漂移、无丢帧；
- 切题、切 Tab、开关面板无闪白、无 1px 布局跳动；
- 动画中途操作能立刻打断接管；
- 高频打字时预览与 UI 不卡顿。

## 9. 交互工艺细则

1. **渐进式显露与克制的空态**
   - 80% 的高频路径要极简直达。高级能力（Typst 插槽覆写、细粒度边距/字号、MCP 集成、外部 OJ 同步配置）放在抽屉或二级页里按需展开。
   - 空工作区、空比赛或没有搜索结果时，不写长篇引导文案，只留克制的视觉留白，加上 **1–2 个最直接的行动入口**（如「新建题目」「拖入 Polygon 包」）。
2. **键盘和全局拖拽都是一等公民**
   - 所有流程都能脱离鼠标完成：`Cmd+K` 命令面板、`Cmd+1..4` 切换空间、`J/K` 或方向键浏览列表、`Esc` 逐层收起浮层或返回上级。只在键盘导航时显示鸭青蓝的 Focus Ring，鼠标点击时不显示。
   - 全局原生拖放：Polygon `.zip`、图片或 `.md` 拖进窗口后，自动识别意图并导入；题库中的题目可以直接拖进比赛里排序。
3. **光学对齐**：图标与文字并排、三角箭头居中等场景，以视觉重心为准，而不是机械的几何居中。
4. **零布局抖动，150ms 防闪烁**
   - Hover、选中、激活 Tab 都不能引起任何 `1px` 的宽度或高度跳变。例如不要靠切换 `font-weight` 来区分状态，因为加粗会撑宽元素；改用颜色、底色或预留宽度。
   - 耗时 `< 150ms` 的原生操作（搜索、增量编译、切题）**不显示 Loading**；加载指示器统一延迟 `150ms` 才出现。
5. **根据上下文智能粘贴**
   - 在编辑器里粘贴截图：自动保存到题目的 `assets/` 并插入规范的图片语法。
   - 在题库视图里粘贴 Codeforces / AtCoder / QOJ 题目链接：自动识别来源和原题 URL。
   - 在样例输入框里粘贴文本：自动清理不可见的 BOM 字符和多余的 `\r`。
